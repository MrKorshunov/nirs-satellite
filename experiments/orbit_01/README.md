# Эксперимент 01 — один КА на круговой орбите

**Цель:** увидеть полёт, проследить происхождение чисел и проверить вычисленный орбитальный участок. Это учебный синтетический опыт, не модель реально запущенного аппарата.

## Технологии
- Численная физика: [Basilisk 2.12.2](https://github.com/AVSLab/basilisk/tree/v2.12.2) (ISC). Основано на документированном API официального [scenarioBasicOrbit](https://avslab.github.io/basilisk/examples/scenarioBasicOrbit.html), без копирования исходного кода Basilisk.
- Проверка: двухтельная формула периода Кеплера и удельной энергии/момента; наши проверки на стандартном Python.
- Графики: matplotlib; трёхмерный просмотр: отдельное приложение [Vizard](https://avslab.github.io/basilisk/Vizard/VizardDownload.html).

## Команды Windows (из корня репозитория)
```powershell
.\.venv\Scripts\python.exe -m experiments.orbit_01.run_orbit
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
start .\results\orbit_01\orbit_3d.png
start .\results\orbit_01\radial_height.png
```

Если Python сообщает `No module named Basilisk`, проверь, что окружение **.venv** создано Python 3.13 и пакет установлен в нём. Не запускай этот сценарий глобальным `py` от Python 3.15.

## Отдельный этап: 3D-визуализация Vizard (Windows)

Полный журнал `orbit_error.txt` показал, что предыдущий сбой был связан с **записью Vizard-файла** на пути проекта, в котором присутствует кириллица (папка «НИР»). Basilisk сообщает `VizInterface: Unable to open file ..._UnityViz.bin for writing`. Подтверждения ошибки физического интегратора в этом логе нет.

Поэтому по умолчанию скрипт **не создаёт интерфейс Vizard**. Сначала запускаем расчёт и получаем `states.csv`, `summary.json`, PNG. Только после проверки включаем экспорт отдельной командой:

```powershell
.\.venv\Scripts\python.exe -m experiments.orbit_01.run_orbit --viz
```

Для экспорта указан **явный файл с расширением `.bin`**: `%LOCALAPPDATA%\NIRS_Satellite\viz\orbit_01.bin`, например `C:\Users\user\AppData\Local\NIRS_Satellite\viz\orbit_01.bin`. Скрипт создаёт его родительскую папку. Это обходит не-ASCII путь проекта и автоматическую поддиректорию `_VizFiles`. Выбранный путь и факт создания записи печатаются в консоль и фиксируются в `summary.json`.

Если путь к `LOCALAPPDATA` сам содержит кириллицу, скрипт предупредит об этом: тогда потребуется задать отдельный доступный ASCII-only каталог. Vizard — отдельная программа для открытия `.bin`, даже если экспорт завершится успешно.

## Исправление инициализации Basilisk (05.11.2026)

Модуль `spacecraft.Spacecraft` (Basilisk 2.11+) требует **строго положительной массы** и **симметричного положительно определённого тензора инерции**. Первая версия этого эксперимента их не указывала, поэтому `InitializeSimulation()` мог завершаться `BasiliskError`. Теперь в `config.json` явно заданы **условные** `hub_mass_kg = 10` и главные моменты `hub_inertia_diag_kg_m2 = [0.12, 0.16, 0.20]`. Эти числа не являются характеристиками конкретного КА и не влияют на двухтельное поступательное движение в данном опыте; они нужны для корректной инициализации динамики корпуса.

Сама масса/инерция не являлись подтверждённой причиной ошибки: полный журнал выявил ошибку записи Vizard-файла. Если новый запуск без `--viz` снова приведёт к `BasiliskError`, необходимо диагностировать её по новому полному журналу.

## Где исходные данные?
`config.json`: радиус сферы Земли 6 378 137 м (принятая WGS84 экваториальная величина), высота 500 000 м, круговая орбита (`e=0`), наклонение 45°, RAAN 30°, прочие углы 0°, шаг 10 с, один виток. **Это искусственная миссия**. `mu` берётся непосредственно из модели Земли Basilisk при выполнении опыта, а не назначается скрытым числом. Все единицы в SI.

## Что сохраняется
`results/orbit_01/` (игнорируется Git как генерируемые данные):
- `states.csv`: момент, положения/скорости в инерциальной системе Basilisk, радиальное расстояние и скорость;
- `summary.json`: все параметры, источник, версия библиотеки, аналитический период, разброс энергии и момента;
- `orbit_3d.png`: неподвижный 3D-график вычисленной траектории;
- `radial_height.png`: высота относительно референсной сферы (основная шкала около 500 км, без научного смещения);\n- `radial_height_deviation_m.png`: отдельно показано малое отклонение высоты от начального значения в метрах (численный эффект в этой двухтельной постановке);
- Vizard-файл `orbit_01.bin` при запуске с `--viz`: записывается **вне проекта**, в `%LOCALAPPDATA%\\NIRS_Satellite\\viz\\` (действует на Windows).

**Как увидеть анимацию:** сначала добейся успешного запуска без `--viz`, затем запусти с `--viz`, установи официальный Vizard для Windows и открой в нём полученный `orbit_01.bin` через выбор файла на стартовом экране. Если `Vizard: not available`, сначала посмотрим графики/лог и разберём доступность модуля; сам расчёт при этом может быть успешным. Vizard — отдельная программа, `pip` её не устанавливает.

Независимая проверка всей траектории после расчёта: `\.venv\Scripts\python.exe -m experiments.orbit_01.validate_orbit`. Подробная методика и расположение исходников: [документ](../../docs/ORBIT_VALIDATION_AND_CODE.md).

## Что проверяем
1. Тесты `test_orbit_analytical.py`: аналитическая формула периода и круговой скорости.
2. После запуска — численно вычисленные `relative_specific_energy_span` и `relative_angular_momentum_span` должны быть малы; их значения **не объявлены заранее**.
3. Вторым запуском уменьшим `time_step_s` с 10 до 5 с и сравним результаты для проверки сходимости. Пока не проводилось.

**Важно:** спутник пока не снимает Землю, не хранит и не передаёт данные. Эти подсистемы — следующая веха после проверенной орбиты.

## Статус проверки
Python-синтаксис и независимые аналитические формулы можно проверить без Basilisk. **Windows подтверждён 05.11.2026:** пользователь предоставил изображения трёхмерной траектории и высоты, вывод расчёта Basilisk 2.12.2: 568 точек, период 94.616 мин, скорость 7.6126 км/с, span энергии 2.895e-11, span момента 1.448e-11. Экспорт `orbit_01.bin (exists=True)` подтверждён; **Vizard открыл модель и показал состояние на времени симуляции 00:06:10**. Автоматические расчёты на Windows и Linux также пройдены. Изменение графика с отдельной шкалой отклонений добавлено позднее и требует повторного просмотра после обновления ветки.
