# ADCS 01 — физическая динамика ориентации и наведение на одну цель

**Статус:** первый эксперимент с физически интегрируемым вращением корпуса спутника. Для анализа готовности наблюдения используется **фактическое направление оси аппарата**, а не искусственный `AttGuidMsg=0`. При этом датчики считаются идеальными, а исполнительным механизмом служит **неограниченный внешний управляющий момент**, поэтому это **НЕ** завершённая аппаратная модель ADCS.

## Задача

На уже работающей физической орбите Basilisk и вращающейся Земле создать замкнутый контур:

```text
Spacecraft.rigid-body state
   -> simpleNav (zero-noise/truth-like)
   -> locationPointing (body +Z toward groundLocation)
   -> mrpFeedback (feedback moment, Nm)
   -> extForceTorque (ideal commanded body torque)
   -> next spacecraft state
```

`groundLocation` одновременно выдаёт **геометрический признак доступа** (угол места). В этом эксперименте он **не используется для остановки наведения**: аппарат непрерывно ориентируется на геометрическое направление к цели, даже когда та скрыта Землёй. Отдельный вычисленный признак `capture_conditions_met` равен единице только если выполняются все три условия:

```text
has_ground_access
AND actual_boresight_error_deg <= readiness_boresight_max_deg
AND tracking_rate_error_rad_s <= readiness_tracking_rate_max_rad_s
```

Это лишь критерий готовности, **никаких кадров или мегабайтов ADCS 01 не создаёт**. Старый `Payload 01` пока использует идеальное наведение, и режимы `--adcs` и `--payload` намеренно несовместимы до самостоятельной проверки их общего управления.

## Как запустить на Windows

Открой PowerShell в корне Git-репозитория, выбери ветку `feature/adcs-01-pointing`.

Сначала только проверка входных параметров:

```powershell
.\.venv\Scripts\python.exe -m experiments.adcs_01.run_adcs --plan-only
```

Затем расчет **12 минут модельного времени** с физическим шагом **0,5 с**:

```powershell
.\.venv\Scripts\python.exe -m experiments.adcs_01.run_adcs
```

Если нужны графики и новая анимация (старую картинку Vizard будет трудно отличить, но теперь **корпус действительно вращается**):

```powershell
.\.venv\Scripts\python.exe -m experiments.adcs_01.run_adcs --viz-mode file --viz-step-s 10
explorer "$env:LOCALAPPDATA\NIRS_Satellite\viz"
```

Открой `adcs_01.bin` в Vizard. Указатель на цель из Ground 01 остаётся на месте, а ориентация корпуса в Vizard теперь изменяется под действием физического управляющего момента. **При разборе ориентации лучше смотреть численные углы**, а не судить по декоративной модели спутника.

## Что сохраняется

Все файлы находятся в `results/adcs_01/` (при `--output-name` в указанном каталоге):

| Файл | Смысл |
|---|---|
| `summary.json` | Исходная орбита, доступность цели, режим запуска и статус геометрических проверок |
| `adcs_summary.json` | Начальная, минимальная и конечная ошибка направления оси на цель, количество пригодных отсчётов, максимальный **командный** момент, пределы интерпретации |
| `adcs_states.csv` | По каждому шагу: фактическая ориентация `sigma_BN`, **угол оси на цель**, ошибка MRP, ошибка угловой скорости, запрошенный момент, геометрическая доступность, готовность |
| `adcs_pointing.png` | График фактической угловой ошибки (градусы), порог готовности, временные окна видимости |
| `adcs_torque.png` | Командный момент (Н·м). **Не** измеренное усилие реальных маховиков |
| `run_manifest.json` | Снимки всех входных конфигураций (Orbit/Ground/ADCS) с SHA-256, версии Basilisk/Python |
| `RESULTS_EXPLAINED.md` | Пояснения на русском, откуда взяты числа и что они значат |
| `access.csv` | Проверенная геометрия орбиты и положения наземной цели |

Сценарий берёт начальные параметры КА из `inputs/physical/orbit.json`, вращение Земли и координаты цели из `inputs/physical/earth_target.json`, а **новые ADCS-параметры** — из `inputs/physical/adcs_ideal_legacy.json`. Все числа в ADCS конфигурации пока **синтетические**, не паспортные.

### Контроль правильности

- Построенная **самостоятельно, без Basilisk**, функция `kinematics.py` переводит физическую ориентацию `sigma_BN` в матрицу ориентации [BN] и угол между телескопической осью в инерциальной системе и вектором к цели. Модуль unit-тестируется на известных углах 0°, 90°, 180° и поворотах о смешанных осях.
- Проверяется ортогональность матрицы, ненулевой запрошенный момент и фактическое изменение ориентации.
- В GitHub Actions модель ADCS сравнивается с **Ground 01 на той же орбите с тем же временным шагом 0,5 с**: геометрическое окно и координаты должны сохраняться в пределах фиксированных допусков.
- Реальное вращение под действием прикладываемого момента не означает реальных ограничений маховиков; следующая веха — конкретные исполнительные органы и насыщение, затем измерения, энергетика и камера.
- Не считать `checks_passed: true` доказательством точной работы реального спутника.

При сравнении шагов 0.5 и 0.25 с разница во время геометрической видимости не превышала 0.000239°, но в начале манёвра на t=2 с достигла 3.43° — этот переходный эффект нельзя скрывать. [Подробный протокол](../../docs/ADCS_01_VERIFICATION.md).
