# Режимы выполнения НИРС: длительность, запись и Live (v0.1)

Обновлено: 06.11.2026. Этот документ относится к **синтетической модели Ground 01 + опциональный Payload 01**. Здесь ещё нет настоящей камеры, ориентации, памяти, радиоканала, энергетики, рельефа и календарной UTC-эпохи.

## Команды Windows

Все команды выполнять **из корня Git-репозитория** с Python 3.13 и установленным Basilisk 2.12.2.

### 0. Проверить план без запуска физического расчёта

```powershell
.\.venv\Scripts\python.exe -m experiments.ground_01.run_ground --duration-days 1 --viz-mode file --viz-step-s 60 --output-name ground_day1 --plan-only
```

Выводится JSON с ожидаемым числом сохранённых состояний, шагом интегрирования, частотой Vizard, длительностью и папкой результата. Значения **предполагаемые** до фактического выполнения.

### 1. Базовый старый вариант — один виток

```powershell
.\.venv\Scripts\python.exe -m experiments.ground_01.run_ground --viz
```

Сохраняется старая совместимость: `--viz` = `--viz-mode file`. Базовая конфигурация `number_of_orbits = 1` в `config.json` остаётся неизменной. Сводка: `results/ground_01/summary.json`; файл для Vizard: `%LOCALAPPDATA%\NIRS_Satellite\viz\ground_01.bin`.

### 2. Одни модельные сутки — записанный файл

```powershell
.\.venv\Scripts\python.exe -m experiments.ground_01.run_ground --duration-days 1 --viz-mode file --viz-step-s 60 --output-name ground_day1
explorer "$env:LOCALAPPDATA\NIRS_Satellite\viz"
notepad .\results\ground_day1\RESULTS_EXPLAINED.md
notepad .\results\ground_day1\run_manifest.json
```

`--duration-days 1`: 86 400 с моделирования. По умолчанию физическая модель и проверка доступности рассчитываются через 10 с — порядка 8 641 сохранённой точки; Vizard при `--viz-step-s 60` получает кадр раз в 60 с модельного времени — ориентировочно 1 441 кадр. **Физика всё равно рассчитывается с шагом 10 с**, визуализация реже. Сохранённая запись не требует прямого соединения Vizard при выполнении вычисления.

После расчёта в Vizard открой `ground_day1.bin`. Скорость просмотра, пауза и перемотка настраиваются **в самом Vizard**, в меню Time; флаг `--speed` на файловое воспроизведение намеренно не действует.

### 3. Неделя без записи Vizard

```powershell
.\.venv\Scripts\python.exe -m experiments.ground_01.run_ground --duration-days 7 --output-name ground_week1
```

При шаге 10 с ожидается 60 481 точка. Это не прогноз действительной орбиты на неделю: текущая динамика двухтельная, Земля сферическая и время не привязано к UTC. Для больших горизонтов память и время на построение графиков растут. При превышении 100 000 ожидаемых точек программа требует осознанный `--allow-large-run`.

### 4. Живая трансляция: DirectComm + синхронизация

```powershell
.\.venv\Scripts\python.exe -m experiments.ground_01.run_ground --duration-hours 2 --viz-mode live --speed 50 --viz-step-s 30 --output-name ground_live_2h
```

**В этом режиме Basilisk ожидает подключения Vizard**. Открой Vizard отдельно, выбери **Direct Communication / DirectComm** и **Live Streaming**, укажи адрес `tcp://127.0.0.1:5556`. Не открывай старый `.bin` — связь с расчётом прямая. Если подключение не выполняется, останови расчёт в PowerShell через Ctrl+C и проверь режим/порт. Порт только для локального компьютера.

`--speed 50` задаёт целевое ускорение расчёта `ClockSynch.accelFactor = 50`: 50 с модельного времени на 1 с настоящего, **если компьютер и Vizard успевают**. Это не гарантия фактической скорости или FPS; liveStream обменивается кадрами синхронно с Vizard. Задавать `--speed` в файловом режиме запрещено, чтобы не смешивать две разные шкалы времени. По умолчанию Live использует 50×, предел проверяемых настроек: 0,1–1000×. На текущем этапе **Live проверен как конфигурация API и без соединения с Vizard; фактический Live-просмотр требует пользовательского опыта на Windows**.

Живая симуляция имеет **конечную** заданную длительность, а не бесконечное вычисление. Это помогает воспроизводимости; позже можно разработать возобновление и более сложный интерфейс управления.

### 5. Payload 01 на два часа

```powershell
.\.venv\Scripts\python.exe -m experiments.payload_01.run_payload --duration-hours 2 --output-name ground_payload_2h
notepad .\results\ground_payload_2h\RESULTS_EXPLAINED.md
```

Геометрия рассчитывается на два часа, но контроллер `Payload 01` **формирует только один условный продукт за весь запуск**. Это не повторная съёмка на каждом новом витке. Позднее добавим перечень целевых задач, обновление расписания и повторные операции.

## Что означает каждая настройка

| Настройка | Что управляет | Чего не изменяет |
|---|---|---|
| `--duration-hours N`, `--duration-days N`, `--orbits N` | Длительность вычисляемого интервала | Физические параметры орбиты |
| `--step-s N` | Шаг численного расчёта и проверки геометрии, с | Высоту КА и скорость Vizard |
| `--viz-mode off/file/live` | Не визуализировать / записать / транслировать | Физические уравнения |
| `--viz-step-s N` | Частота кадров визуализации, шаг в модельных секундах | Частоту расчёта динамики |
| `--speed N` | Целевое ускорение **только Live**, × | Модельную длительность и точность интегрирования |
| `--output-name slug` | Отдельная папка `results/slug` и файл `slug.bin` | Исходный `config.json` |
| `--plan-only` | Проверка конфигурации без расчёта | Не создаёт результаты физического моделирования |

Не разрешается задавать одновременно `--duration-hours`, `--duration-days` и `--orbits`. Шаг Vizard должен быть целым кратным шагу физики.

## Проверяемость и происхождение

**Каждый законченный запуск** создаёт файлы:
- `summary.json`: реальные численные значения, окна видимости, проверки, параметры запуска;
- `run_manifest.json`: точные JSON орбиты и Ground 01 (и Payload 01, если используется), SHA-256 их содержимого, версия Basilisk/Python, ОС, словарь входных параметров и результатов;
- `RESULTS_EXPLAINED.md`: пояснения на русском «что задано», «что получилось» и какие выводы **нельзя** делать;
- `access.csv`: временной ряд с единицами в именах колонок;
- `elevation.png`, `slant_range.png`: графики; при Payload 01 — отдельный журнал событий.

Учитываются **три разных времени**:
1. **Физическое модельное время:** момент времени в `access.csv`, 0…горизонт, шаг динамики.
2. **Периодичность Vizard:** как часто публикуется визуальный кадр (может быть реже).
3. **Настоящее время:** сколько занимает выполнение и просмотр; Live может ограничивать скорость через `ClockSynch`, а файловый просмотр управляется Vizard независимо.

**Ограничения:** синтетический одновитковый исходник, двухтельное движение, равномерное вращение сферической Земли без UTC, одна точка, геометрия вместо полноценной оптической съёмки, один условный продукт, нет полноценной бортовой памяти/радиоканала. Длинный прогон **не повышает** точность модели сам по себе.
