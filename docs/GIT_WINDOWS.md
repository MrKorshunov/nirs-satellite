# Обновление НИРС через GitHub Desktop

Инструкция для уже созданного репозитория `MrKorshunov/nirs-satellite`. Обычный запуск программы не требует PowerShell.

## Если репозиторий уже клонирован

Если копия есть на диске, но её нет в списке GitHub Desktop, выбери **File → Add Local Repository** и укажи существующую папку проекта. Не клонируй её повторно.

1. Открой GitHub Desktop и выбери `nirs-satellite` в списке репозиториев.
2. Убедись, что выбрана ветка `main`.
3. Нажми **Fetch origin**. Если появились обновления, нажми **Pull origin**.
4. Если GitHub Desktop показывает локальные изменения, сначала просмотри их. Сохрани нужную работу отдельным commit или резервной копией; не нажимай **Discard changes** для очистки перед обновлением.
5. Открой папку через **Repository → Show in Explorer**.
6. Если обновились зависимости, исходники физической модели или команда проверки, запусти `SETUP_NIRS.cmd`. Для обычного обновления документации повторная установка не нужна.
7. Для запуска дважды щёлкни `START_NIRS.cmd`.

Кнопка **Pull origin** появляется, только если выбранная ветка отстаёт от удалённой. Если GitHub Desktop сообщает о конфликте, остановись и сохрани копию своих изменений перед разрешением конфликта.

## Если репозиторий ещё не клонирован

1. В GitHub Desktop выбери **File → Clone repository**.
2. Найди `MrKorshunov/nirs-satellite` либо вставь адрес `https://github.com/MrKorshunov/nirs-satellite.git`.
3. Выбери папку для локальной копии и нажми **Clone**.
4. Дальше выполни шаги установки из [руководства Windows](WINDOWS_GUI_GUIDE.md).

Скачивание ZIP остаётся запасным вариантом, но GitHub Desktop удобнее для последующего получения обновлений.

## Публикация своих изменений

GitHub Desktop не отправляет изменения автоматически. Чтобы опубликовать собственную работу, проверь вкладку **Changes**, введи короткое описание в поле **Summary**, нажми **Commit to …**, затем **Push origin**. Для экспериментальной разработки сначала создай отдельную ветку через **Branch → New branch**.

Не добавляй в commit папку `results/`, виртуальную среду `.venv/` или локальные резервные копии входных JSON-файлов: они предназначены для локальной работы и исключены из Git.
