# Git для НИРС: Windows, первые шаги

Git **локально** отслеживает версии, GitHub/GitVerse позволяет хранить копию и видеть историю в браузере. **Не загружайте чужой исходный репозиторий вместо своего.**

## 1. Проверка установки

Откройте PowerShell в папке `NIRS_satellite_v0_1_1` и введите `git --version`.
Если команда не найдена, скачайте Git с https://git-scm.com/install/windows и откройте PowerShell заново.

## 2. Представиться Git (делается один раз на компьютере)

```powershell
git config --global user.name "Mark Korshunov"
git config --global user.email "АДРЕС_ВАШЕЙ_ПОЧТЫ"
```

Имя/почта нужны для подписи коммитов. Не включайте в репозиторий пароли или токены.

## 3. Создать историю в существующей папке

```powershell
git init
git branch -M main
git status
git add .
git commit -m "v0.1.1: documented simulation inputs and trace"
```

`git status` — проверить изменения; `git add .` — подготовить текущие файлы; `git commit` — зафиксировать версию. Программа от этих команд не меняется.

## 4. Связать со своим удалённым репозиторием

Создайте **пустой** репозиторий `nirs-satellite` на GitHub или GitVerse. Для начала лучше выбрать **Private**. Не добавляйте туда отдельно README или .gitignore: они уже есть в локальном проекте.

Скопируйте **реальный HTTPS URL** нового репозитория и выполните:

```powershell
git remote add origin ВАШ_HTTPS_URL
git push -u origin main
```

В отличие от `git commit`, отправка `git push` публикует текущую версию на вашем сервисе. Сервис может запросить вход через браузер/менеджер учётных данных.

## 5. Ежедневный цикл

```powershell
git status
git diff
git add .
git commit -m "Кратко что изменено"
git push
```

Если изменения появятся в удалённом репозитории или на другом компьютере, до новой работы используйте `git pull`.

## Что где смотреть

- **Code / Файлы:** `nirs_satellite/` (модель), `scenarios/` (исходные данные), `tests/` (проверки), `results/` (примеры выходов), `docs/` (пояснения).
- **Commits / История:** кто, когда и какие строки изменил.
- **Issues / Задачи:** что запланировано, что в работе, что завершено. Начните с переноса задач из `TASKS.md`.
- **README.md:** как запустить и где посмотреть текущий результат.

Git не заменяет научную проверку. История показывает, *что изменилось*, а файлы `docs/INPUT_DATA.md` и `results/report.html` объясняют, *откуда и почему получен результат*.
