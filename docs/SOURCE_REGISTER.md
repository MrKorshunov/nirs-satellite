# Реестр моделей, библиотек и исходных данных

Актуализация: 05.11.2026. Указана **область применения и план проверки**, а не автоматическое подтверждение физической достоверности всех моделей.

| Часть будущей программы | Предлагаемый открытый источник | Что используем | Ограничение и независимая проверка |
|---|---|---|---|
| Орбита, ориентация, съёмка, бортовая память, передача | [Basilisk](https://avslab.github.io/basilisk/) / [scenarioGroundLocationImaging](https://avslab.github.io/basilisk/_modules/scenarioGroundLocationImaging.html), [код](https://github.com/AVSLab/basilisk), ISC | Модули `spacecraft`, `groundLocation`, `locationPointing`, `simpleInstrument`, `partitionedStorageUnit`, `spaceToGroundTransmitter` | Пример — **модель абстрактных данных**, а не сертифицированная гиперспектральная камера или готовый радиолинк; проверить единицы, шаг времени, ограничения и баланс |
| Геометрическое покрытие и исследование конфигураций группировок | [TAT-C](https://tatc.readthedocs.io/), [код](https://github.com/code-lab-org/tatc), BSD-3-Clause | Оценка возможностей наблюдения и конфигураций при проектировании | Сам по себе не решает нашу задачу доставки данных/выбора операций; сопоставить окна с независимой моделью |
| Независимый контроль орбит и координат | [SatKit](https://satkit.dev/) или [Skyfield](https://rhodesmill.org/skyfield/earth-satellites.html) | Трансформации систем координат, SGP4 (для **существующих TLE**), контроль окон | Не использовать TLE вымышленного проектируемого КА как физически подтверждённую орбиту; контролировать эпохи, шкалы времени и системы координат |
| Точное расписание малых дискретных задач | [Google OR-Tools CP-SAT](https://developers.google.com/optimization/cp/cp_solver), [код](https://github.com/google/or-tools), Apache-2.0 | Интервальные/целочисленные ограничения, `NoOverlap`, оптимизация | Только дискретная модель; указать шаг сетки и статус `OPTIMAL`/`FEASIBLE`; независимо сверить полным перебором на малых задачах |
| Гиперспектральные данные | [Simera Sense HyperScape100](https://simera-sense.com/products/hyperscape100/) и точная редакция паспорта | Разрешение, число каналов, битность, режимы и ёмкость | Не смешивать поколения документации: **есть паспорта с различной разрядностью и диапазонами**; фиксировать версию перед расчётом |
| Облачность — поздний этап | [ERA5](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview), Sentinel-2 L2A SCL | Временные погодные сценарии, маска пригодной площади | ERA5 — реанализ, не оперативный прогноз; SCL — классификация пикселей в моменты съёмки, не непрерывное наблюдение погоды |
| Исходный учебный репозиторий | [GitVerse python_for_bmstu_students](https://gitverse.ru/zayn/python_for_bmstu_students) | Сравнение структуры и функций; возможно математические идеи | Права на перенос кода не установлены; **пока не копировать** и не считать протестированным |

## Научные постановки, которые нужно сопоставить
- Rocha et al., 2025 — [совместное планирование съёмки и передачи](https://www.cirrelt.ca/documentstravail/cirrelt-2024-28.pdf), математические ограничения и benchmark.
- Zhu et al., 2026 — DOI 10.1016/j.ast.2025.111571, планирование с учётом доставки в срок.
- Valicka et al., 2019 — DOI 10.1016/j.ejor.2018.11.043, стохастические расписания при облачности.
- Paek et al., 2018 — DOI 10.1016/j.asr.2018.07.012, выбор орбитальной группировки по требованиям.
- Дарнопых и соавторы, 2013–2014 — проектирование группировки на основе планирования целевой работы (см. `RESEARCH_CONTEXT.md`).

**Что наше:** смысл целевого задания, правило зачёта **после доставки**, алгоритмы сравнения, проверка влияния планирования на необходимое число КА, экспериментальный протокол. Новизна не гарантируется и проверяется сравнением с близкими работами.

## Совместимость Windows
- У пользователя установлен Python 3.15 x64; текущая v0.1 работает в нём.
- **Отдельное исследовательское окружение: Python 3.13 x64** — рабочий выбор для Basilisk, TAT-C и OR-Tools.
- Basilisk 2.12.2 на PyPI требует `Python <3.15` и имеет wheel для Windows x64.
- TAT-C 3.6 документация указывает Python 3.10–3.14.
- OR-Tools 9.15 имеет wheel для Windows/Python 3.13.
- Пакеты **пока не установлены и не испытаны на пользовательском компьютере**. Версии зафиксировать при первом успешном запуске.

## Реестр параметров сценария (будущая схема)
Для каждого численного значения фиксировать:
`parameter_id | value | unit | source_url_or_document | source_revision | origin_type [datasheet/calculated/synthetic/observed] | uncertainty | checked_on`.

Начальный `scenarios/demo.json` полностью синтетический. Ни одно его значение не является валидацией реального КА.

## Отбор библиотек
1. Подтвердить лицензию и совместимость окружения.
2. Запустить официальный пример без изменения физической модели.
3. Зафиксировать конфигурацию, версии зависимостей и журналы.
4. Сверить минимум один расчёт с независимым эталоном.
5. Подключать через адаптер, без копирования исходников и без скрытой подмены физических допущений.
