# Репозиторий НИРС — инструкция разработчику

## Правило: пользовательский вход отделён от программы

- Числа вводим **только** в [inputs/](../inputs/README.md) (или через редактор GUI).
- Физику/сценарии Basilisk меняем в `experiments/`.
- GUI и выбор файлов — `nirs_satellite/`.
- Пишем проверки в `tests/` и держим зелёными CI Windows/Linux.
- `results/` — локальные сгенерированные отчёты, не загружаются в Git.
- Архивный FIFO/EDF v0.1 — `archive/v01/` и только для истории.

## Порядок работы

1. Открыть репозиторий в VS Code или GitHub Desktop.
2. Создать ветку от `main` под одну конкретную инженерную задачу.
3. Изменить нужные параметры или компонент, записать происхождение новых чисел и модельные допущения.
4. Запустить `CHECK_NIRS.cmd`. Для физической интеграции проверить также CI Windows/Linux.
5. Сохранить конфигурацию, версию коммита, отчёты и графики. Открыть PR со списком проверок.
6. Слить в `main` только при успешном результате и сохранении совместимости.

## Что не следует делать

- Не переносить импортируемые Python-пакеты `experiments` без параллельной правки тестов, CI и модульных путей.
- Не копировать одинаковые параметры в `experiments/*/config.json`: здесь специально установлен единый реестр `nirs_satellite/input_paths.py`.
- Не смешивать Mission 01 и Mission 02, пока между ними нет физической обратной связи.
- Не выдавать пример с условной эпохой, одной съёмкой и диагностической батареей за полноценный цифровой двойник.
- Не удалять старые протоколы с результатами; для истории есть `docs/history/` и `archive/v01/`.

Главный план дополняется по мере разработки [WHAT_IS_MISSING.md](WHAT_IS_MISSING.md). Точные связи кода описаны в [CODE_MAP.md](CODE_MAP.md).
