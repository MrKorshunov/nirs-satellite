### Самостоятельная геометрическая оценка

По сферической геометрии и высоте 500 км минимальную дальность для максимального угла места можно оценить как
```
rho = -R*sin(e) + sqrt((R+h)^2 - R^2*cos(e)^2).
```
Подстановка пользовательского значения `e=86.35830073375627°` даёт `rho ≈ 500.937916125 км`, а в JSON `500.937916028 км`. Разница порядка 0.0001 м. Это **проверка внутренней согласованности** двух показателей при круговой орбите, а не независимая внешняя валидация.

На графике дальности приблизительно 13 000 км в дальней части витка не означают видимость: это прямая геометрическая дистанция через Землю, соответствующий угол места отрицателен.

## 3. Найденная и исправленная ошибка в отчёте о границах окна

В присланном `summary.json`:
```json
{"first_access_sample_s":90,"first_inaccessible_sample_s":550,"duration_upper_bound_s":460}
```
Значение **460 с неправомерно именовалось верхней границей**. Момент перехода через порог нельзя восстановить из одних дискретных отметок, не задавая интерполяцию.

При условии одного непрерывного перехода между соседними отсчётами:
- предыдущий недоступный отсчёт 80 с, первый доступный 90 с → начало в интервале **80–90 с**;
- последний доступный 540 с, следующий недоступный 550 с → конец в интервале **540–550 с**;
- длительность окна находится в пределах **450–470 с** (7 мин 30 с — 7 мин 50 с).

Исправлено в `experiments/ground_01/geometry.py`: добавлены `last_access_sample_s`, соседние отсчёты, границы возможных моментов перехода, `duration_lower_bound_s` и настоящая `duration_upper_bound_s`. Значения 450 и 470 с ожидаются **только после повторного запуска обновлённой версии**. Для окон, пересекающих границу симуляции, неизвестная верхняя граница теперь `null`, а не искусственно экстраполируется.
