# Исходные данные НИРС — единый реестр

**Единственный актуальный каталог для редактирования чисел — [inputs/](../inputs/README.md).** Каждое изменение сохраняет происхождение `provenance: SYNTHETIC...`. Полная численная пригодность проверяется при запуске соответствующей модели; редактор проверяет формат и обязательные поля.

## Физическая модель одного КА

| Файл | Содержит | Пример условных параметров |
| --- | --- | --- |
| [physical/mission_execution.json](../inputs/physical/mission_execution.json) | **Две физические цели, порядок, энергетический резерв, такт управления** | 2 цели, 5 с |
| [physical/orbit.json](../inputs/physical/orbit.json) | Кеплеровы элементы, масса, инерция | 500 км, наклонение 45°, 10 кг |
| [physical/earth_target.json](../inputs/physical/earth_target.json) | Равномерное вращение условной Земли и координаты первой цели | 14° с. ш., 43° в. д., min elevation 10° |
| [physical/adcs_wheels.json](../inputs/physical/adcs_wheels.json) | Начальная ориентация, коэффициенты регулятора, три маховика, момент и скорость | 0,01 Н·м, 950 об/мин на колесо |
| [physical/power.json](../inputs/physical/power.json) | Батарея, панель, КПД, нагрузки, условный вектор Солнца | 80 Вт·ч ёмкость, 65 Вт·ч начальный заряд, 0,08 м² |
| [physical/camera_storage_radio.json](../inputs/physical/camera_storage_radio.json) | Объём условного продукта, ёмкость памяти, скорость связи, станция | Снимок 1 МБ, память 4 МБ, передача 160 кбит/с |
| [physical/camera_storage_radio_slow.json](../inputs/physical/camera_storage_radio_slow.json) | Контрольный сценарий с медленным каналом | 10 кбит/с |
| [physical/adcs_ideal_legacy.json](../inputs/physical/adcs_ideal_legacy.json) | Старый режим идеального момента | Только историческое сравнение |
| [physical/payload_demo_legacy.json](../inputs/physical/payload_demo_legacy.json) | Изолированная ранняя проверка генерации данных | Не основной сценарий |

**Важная связь:** файл `earth_target.json` содержит `orbit_config_path: "orbit.json"` — именно так физический раннер находит орбиту. Все эти числа условные, а начальная эпоха вращения Земли не задана в UTC.

## Многозадачные контрольные эксперименты

| Файл | Содержит |
| --- | --- |
| [research/observation_tasks.json](../inputs/research/observation_tasks.json) | Набор условных наземных целей, приоритеты, время появления заданий и дедлайны, объёмы данных, экспозиция, станции, память, упрощённые электроэнергетические и радиочастотные параметры |

**Предупреждение:** `observation_tasks.json` — набор параметров отдельной упрощённой операционной модели. Изменение массы, памяти или связи там **не изменяет автоматически** соответствующий файл физического сценария. Их численное согласование — следующий этап.

## Эпоха UTC, расписание и WGS84 (Mission05)

В `inputs/physical/mission_mixed_demo.json` вводятся `epoch_utc` (ISO 8601 c `Z`), `dut1_seconds` (поправка UT1−UTC), `planned_start_s` и `planned_end_s` в каждой задаче. Список `downlink_windows` задаёт отдельные плановые интервалы передачи. Внешний план через `--program` может передать собственные задачи и окна. **Порядок не оптимизируется** — исполняется входной.

`inputs/physical/territories.json` теперь использует геодезические координаты WGS84. Полигональная метрика покрытия вычисляется как площадь **объединения и отсечения геометрических модельных следов** камеры по области в равновеликой проекции. Для задания полосы необязательное поле `min_coverage_percent` устанавливает порог результата независимо от количества `min_samples` / `max_samples`.

**Важно:** дата и широта/долгота теперь задаются явно, но долгота Earth/GMST приблизительная; для точных пролётов конкретного КА нужны UT1/EOP, согласованные эфемериды и проверка погрешностей. [Технический отчёт Mission05](SCIENTIFIC_READINESS_MISSION05.md).

## Универсальная программа точек и полос

| Файл | Содержит |
| --- | --- |
| [physical/mission_mixed_demo.json](../inputs/physical/mission_mixed_demo.json) | Упорядоченные задания `point` / `strip`, сроки, размеры цифровых порций и FOV |
| [physical/territories.json](../inputs/physical/territories.json) | Многоугольники регионов в градусах широты/долготы синтетической вращающейся Земли |

В результате физического прогона появятся `mission03_groundtrack.csv` и `mission03_strip_footprints.csv` для проверки пересечения трассы с территориями. Если `epoch_utc` не задан, используется условная эпоха; Mission05 допускает явную UTC-эпоху и приближённую GMST по правилам выше. [Точный формат](UNIVERSAL_EXECUTOR_AND_STRIP.md).

## Как вводить значения

В Windows дважды откройте `START_NIRS.cmd` → **«Все исходные данные»** → выберите из списка раздел → измените JSON → «Проверить JSON» → «Сохранить с резервной копией». Формируется рядом файл `.json.bak`. Можно редактировать те же файлы через VS Code.

Не следует одновременно менять код и исходные данные без записи набора изменений. Для сравнения двух запусков сохраняйте копию конфигурации, версию Git (коммит), имя результата, шаг времени, алгоритм и допущения. Mission 02 автоматически пишет конфигурацию, манифест, SHA-256 орбитального трека и результаты; физический сценарий пишет входные конфигурации и хеши в манифест.

## Какие исходные данные нельзя пока полноценно задать только через JSON

- Реалистичный момент и насыщение магнитных катушек, разгрузка маховиков, датчики и модель ошибок измерений.
- Настоящая оптика камеры, геометрия пикселя, качество изображения, сжатие, длительные экспозиции и механика наведения прибора.
- Наземный приёмник, протокол связи, подтверждение доставки, кодирование, ошибки пакетов, атмосферные потери.
- Автоматическое отключение аппаратуры при нехватке энергии и расписание режимов всех потребителей.
- **Высокоточные** IERS EOP/полярное движение/прецессия/нутация, достоверные эфемериды КА на реальную эпоху и J2/атмосферное торможение по требуемой точности. Простая UTC+GMST и WGS84 аппроксимация уже доступна.
- Алгоритма поиска оптимального расписания нет, но исполнитель уже принимает **внешний JSON с 1–64 упорядоченными точками и полосами** через `--program`. Оптимизация будет отдельным этапом.

Для их ввода ещё нет законченных модельных интерфейсов: одних новых чисел в JSON недостаточно — требуется расширять код и проводить проверки.

Единицы: метры, килограммы, секунды, радианы и градусы по именам полей; `bytes` — байты, `bits_per_s` — биты/с, `Wh` — ватт-часы. Не следует смешивать их при изменении входа.
