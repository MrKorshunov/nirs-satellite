# Запуск НИРС на Windows без PowerShell

**Основной файл для старта:** `START_NIRS.cmd` в корневой папке проекта.

## Первоначальная настройка (один раз)

1. Загрузите репозиторий через **Code → Download ZIP** на GitHub и распакуйте, например, в `C:\NIRS\nirs-satellite`. Для обновлений удобнее GitHub Desktop.
2. Установите **Python 3.13 (x64)** с Windows Python Launcher с сайта https://www.python.org/downloads/ . Если Python уже есть, повторно устанавливать его не нужно.
3. В папке проекта дважды щёлкните **`SETUP_NIRS.cmd`**. Скрипт создаёт локальную `.venv`, устанавливает Basilisk 2.12.2 и проверяет Python/GUI. На этом этапе потребуется интернет.
4. Дважды щёлкните **`START_NIRS.cmd`**. Откроется окно НИРС. Никакого PowerShell для обычной работы не требуется.
5. По умолчанию стоит **«Физическая модель»** с длительностью 0,2 ч. Нажмите **«Запустить»**. После выполнения используйте **«Открыть результаты»**.
6. Для просмотра в Vizard нажмите **«Папка Vizard»** и откройте запись `.bin` в установленном приложении Vizard через режим воспроизведения файла.

## Режимы интерфейса

| Режим | Назначение |
| --- | --- |
| Физическая модель | Орбитальная динамика и ADCS через Basilisk, три реакционных маховика с ограничениями, физические модули затмения/панели/батареи, одна условная съёмка, память, передача данных, запись Vizard |
| Проверка планирования | Несколько синтетических заданий, FIFO/EDF/Priority, ограничения манёвров, угла наблюдения, памяти, заряда, радиоканала и времени сдачи. Здесь действуют собственные упрощённые формулы ресурсов |
| Автоматические проверки | Проверка Python-логики; без Vizard и без создания результатов моделирования |

Результаты формируются в `results/ИМЯ_ЗАПУСКА/`. Программа каждый раз предлагает новое имя. Кнопка «Остановить» прерывает текущий процесс и его дочерние процессы. Неполные отчёты нельзя считать завершёнными экспериментами.

## Где изменять условные характеристики

Кнопка «Настройки JSON» открывает основные параметры выбранного режима. Физическая модель собирает настройки из нескольких файлов:

- `experiments/orbit_01/config.json` — орбита, масса, моменты инерции;
- `experiments/ground_01/config.json` — вращение Земли и география цели;
- `experiments/adcs_02/config.json` — регулятор и параметры реакционных маховиков;
- `experiments/power_01/config.json` — аккумулятор, солнечная панель, условное Солнце;
- `experiments/mission_01/config.json` — полезная нагрузка, бортовая память, радиоканал;
- `experiments/mission_02/config.json` — задания и условные ресурсы для сравнения алгоритмов.

Изменения рекомендуется проводить по одному, сохраняя копии старых JSON. Физическая Mission 01 пока рассчитана на **один продукт** и фиксированный физический шаг 0,5 с. Многозадачный Mission 02 пока не воспроизводит все манёвры в динамике Basilisk.

## Vizard: как это работает

Графический лаунчер формирует файл записи в папке `%LOCALAPPDATA%\NIRS_Satellite\viz\`. Кнопка «Папка Vizard» открывает её. Vizard должен быть установлен отдельно. В приложении можно проиграть, ускорить и перемотать полёт; скорость воспроизведения не меняет физический шаг.

## Нужно ли устанавливать среду разработки?

**Для запуска нет.** Для редактирования и разработки рекомендую бесплатный **Visual Studio Code** с расширением Python от Microsoft: https://code.visualstudio.com/ .

В VS Code выберите **File → Open Folder**, откройте папку репозитория, а в **Python: Select Interpreter** укажите `.venv\Scripts\python.exe`. Встроенная конфигурация отладки позволяет запускать сценарии из IDE. Если нужна более визуальная работа с Git, можно поставить GitHub Desktop: https://desktop.github.com/ .

## Неполадки

Если окно не запускается — сначала выполните `SETUP_NIRS.cmd` и посмотрите, завершена ли установка успешно. Файл `CHECK_NIRS.cmd` позволяет провести проверку двойным щелчком без PowerShell. Если симуляция завершилась ошибкой, скопируйте последние строки из окна журнала.

## Важная оговорка о достоверности

Физическая модель Basilisk на демонстрационных параметрах — **не цифровой двойник конкретного КА**. Нет полностью реалистичных датчиков, физического отключения приборов при разряде, реального приёмника с ACK/BER и формирования пикселей изображения. В совместной физической Mission 01 нагрузки камеры и передатчика включены на весь расчёт как верхняя оценка; многозадачный сценарий использует упрощённую ресурсную модель. Все эти упрощения зафиксированы, чтобы позже заменить их характеристиками выбранного аппарата.
