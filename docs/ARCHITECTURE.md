# Архитектура: что берём готовым, что исследуем

## Назначение
Из списка наблюдений, ограничений ресурсов и рассчитанных окон допустимых операций сформировать расписание, воспроизвести его и оценить выполнение задания **после полной доставки пригодных данных в срок**.

```text
scenarios + источники параметров
          |
          v
[Адаптер физики] -> допустимые окна съёмок и связи
          |              (сначала synthetic, затем TAT-C/Basilisk)
          v
[Планировщик] -> операции съёмки / сброса -> [Исполнитель/симулятор]
                                             |
                                             v
                                   журналы памяти/передач
                                             |
                                             v
                                   [Независимый оценщик]
                                             |
                                             v
                                    KPI и сравнение N КА
```

## Границы ответственности
| Модуль | Отвечает за | Источник / статус |
|---|---|---|
| `mission` | Цели, задания, сроки, веса, качество | Наш код: специфика нашей научной задачи |
| `geometry adapter` | Окна наблюдений/связи, освещение, видимость | Вначале фиксированные окна; затем внешняя библиотека и независимая проверка |
| `payload adapter` | Объём данных: пиксели × строки × спектральные каналы × биты/отсчёт | Формула и паспорт прибора; упаковку и сжатие задавать явно |
| `resources` | Бортовая память, операции, очередь передачи; энергия позже | На v0.1 — собственная проверяемая модель; для физического контура рассматриваем Basilisk |
| `scheduler` | Выбор допустимых съёмок и передач | Наши baseline/собственный метод, OR-Tools CP-SAT для малого эталона |
| `evaluator` | Зачёт по доставке в срок, задержка, потери, причины | Наш независимый код |
| `experiment runner` | Фиксация сценариев, версий и сравнение методов | Наш код |

**Не интегрировать разные орбитальные движки как параллельные владельцы одного состояния.** Геометрию выдаёт ровно один выбранный адаптер; другой инструмент используется только как независимый эталон для проверки.

## Приоритет реализации
0. **Сохранить стабильный контрольный пример v0.1.1.** Его результаты синтетические.
1. **v0.2:** выбор съёмок из нескольких окон, ограничения, базовые алгоритмы, полный перебор на малых примерах; всё пока без орбиты.
2. Подключить оконную геометрию от выбранной библиотеки без изменений интерфейса планировщика.
3. Подключить проверяемую энергетику/ориентацию и модель объёма гиперспектральных продуктов.
4. Расширить до N КА, общий ресурс наземных станций, сравнение конфигураций.
5. Погодные сценарии и итоговые вычислительные эксперименты после калибровки качества.

## Инварианты
- Снимок не возникает до завершения съёмки; объём данных не становится отрицательным.
- Нельзя превысить лимит накопителя или скорость/время сеанса связи.
- Передача после срока не считается успешным выполнением.
- Планировщик не знает будущую фактическую облачность.
- В одинаковых сценариях методы получают идентичные данные.
- Отдельно хранить статус допущения, паспортного параметра и вычисленного значения.

## Статус
Это **план архитектуры**, а не список реализованных интерфейсов. Не переносить текущие файлы и не подключать тяжёлые зависимости до появления регрессионных тестов и первого адаптера.
