# НИРС — текущее состояние проекта

**Дата фиксации:** 04.11.2026  
**Версия кода:** 0.1.0  
**Направление:** оптимизация выполнения целевых задач ДЗЗ с учётом
ресурсов КА, хранения и доставки данных; сначала заданный КА, затем
сравнение состава группировок.

## Реально сделано

1. Через общедоступные страницы GitVerse просмотрена структура исходного
   `zayn/python_for_bmstu_students`, а также код `ballistic.py`,
   `mission_simulation.py`, параметры зависимостей и перечень тестов.
2. Создан самостоятельный минимальный дискретно-событийный имитатор
   информационного цикла для одного КА — **с заранее заданными съёмками**.
3. Реализована проверка памяти, последовательная передача, сроки доставки,
   FIFO и EDF, журнал событий, экспорт результатов.
4. Написаны и запущены автоматические тесты; результаты команд запуска
   записаны в разделе ниже.
5. Сохранены входные данные демонстрации и результаты для повторения.

## Что не сделано

- Оригинальный репозиторий GitVerse не клонирован и его тесты не запускались:
  в текущей среде попытка `git ls-remote` завершилась ошибкой разрешения DNS.
- Не реализован выбор момента съёмки / отказ от съёмки в пользу другой задачи.
- Отсутствуют орбитальная геометрия, энергия, облачность, несколько КА.
- Не выполнена независимая проверка физической достоверности.
- Научная новизна и превосходство методов **не установлены**.

## Контрольные команды и фактический результат

Тестирование в изолированной среде Python 3.13.5, стандартная библиотека:

```
python -m unittest discover -s tests -v
# Ran 14 tests — OK

python main.py

# EDF: K=0.667, on time=['A_fields', 'B_water'], rejected=['C_forest']
```

Испытания на локальном компьютере пользователя ещё не проведены.

## Ближайший технический шаг — v0.2

1. Дать каждому заданию **набор допустимых окон съёмки**, а не один
   заранее назначенный интервал.
2. Реализовать выбор съёмок с конфликтами по времени и памятью.
3. Сравнить два правила планирования всей цепочки «съёмка → доставка».
4. Для малой задачи сделать независимый полный перебор как эталон.
5. Повторить тесты и сформировать первую таблицу сравнения планировщиков.

Сложную орбитальную модель и группировку не подключать до этого этапа.

## Что может потребоваться от пользователя

- Для полноценной проверки оригинала GitVerse: архив `satellite_model` или
  доступ к локальному клону, если прямое клонирование недоступно здесь.
- Для запуска на личном компьютере: результат выполнения команд из README.
- Полученные от авторов статей PDF — для окончательной научной постановки;
  **не блокируют** v0.2.

## Правило сохранения

После каждого этапа менять этот файл и `CHANGELOG.md`; делать коммит Git
и копию ZIP. Наиболее актуальное состояние — по фактическим тестам, а не
по заявленным планам.
