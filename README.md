# НИРС — планирование целевых операций КА и оценка группировок

**Состояние:** исходный информационный прототип v0.1.1, а в отдельных рабочих PR — физическая орбита Orbit 01, вращающаяся Земля и видимость Ground 01, условная генерация данных Payload 01. Эти этапы проверены на Windows пользователя; реальные наведение, память, передача и оптимизация ещё не интегрированы. В PR #10 экспериментально добавляется управление временем расчёта и воспроизведением.

> **Новому участнику:** откройте [«С чего начать»](docs/START_HERE.md), затем [архитектуру](docs/ARCHITECTURE.md) и [реестр открытых источников](docs/SOURCE_REGISTER.md). Все результаты v0.1.1 получены на искусственных входных данных.

## Начало работы на Windows

```powershell
py main.py
py explain.py
py -m unittest discover -s tests -v
start .\results\report.html
```

Базовый прототип v0.1.1 использует стандартную библиотеку Python. Для орбитальных сценариев используется отдельное окружение **Python 3.13 + Basilisk 2.12.2**; установленная библиотека уже проверена в Windows.

## Что находится в репозитории

- `nirs_satellite/`: модель заданных съёмок, памяти и передачи; сравнение очередей FIFO и EDF.
- `scenarios/demo.json`: **синтетический** контрольный сценарий (НЕ паспорт реального КА).
- `tests/`: автоматические тесты.
- `docs/INPUT_DATA.md`, `docs/MODEL_STEP_BY_STEP.md`: происхождение чисел и пошаговая трассировка.
- `results/`: результаты демонстрации (в будущем разделим эталонные и генерируемые).
- `TASKS.md`, `PROJECT_STATE.md`, `DECISIONS.md`, `CHANGELOG.md`: план, статус, решения, версии.

## Что исследуем

1. При заданном составе спутников сравнить методы планирования наблюдений и передачи данных для максимизации доли заданий, доставленных в срок.
2. Определить, как изменение метода планирования влияет на минимальную численность группировки для одной и той же программы наблюдений.

Не путать работающий прототип с физически валидированной спутниковой моделью. На v0.1.1 программа **не выбирает окна съёмок**, а только порядок передачи уже назначенных продуктов. Технические и научные ограничения см. [START_HERE](docs/START_HERE.md).

## Длительные расчёты и объяснение результатов (экспериментальная ветка PR #10)

Инструкции: [SIMULATION_CONTROL.md](docs/SIMULATION_CONTROL.md). [Проверки Linux/Windows](docs/SIMULATION_RUN_VALIDATION.md). Системная карта: [SYSTEM_STATUS.md](docs/SYSTEM_STATUS.md).

- Выбираем длительность в часах или сутках.
- Отдельно задаём шаг физической модели, записи данных и кадров Vizard.
- Сохраняем исходные параметры, происхождение и расшифровку показателей рядом с каждым запуском.
- Прямая передача в Vizard добавлена как **экспериментальный** режим; её необходимо проверить с открытым Vizard на Windows пользователя.

Пример численного расчёта одних модельных суток:

```powershell
.\.venv\Scripts\python.exe -m experiments.ground_01.run_ground --days 1 --record-step-s 30 --output-name ground_day1
```
