# НИРС — моделирование информационного цикла КА (v0.1)

Это **первый проверяемый прототип** программной части НИРС об оптимизации
выполнения программы наблюдений отдельным КА и группировкой. Проект
является самостоятельным кодом и пока **не интегрирован** с GitVerse.

## Что уже работает

- Синтетические задания фиксируют начало и конец съёмки, объём данных,
  срок доставки и вес/приоритет.
- После завершения съёмки появляется продукт в памяти; при переполнении
  снимок отклоняется.
- Один радиоканал передаёт данные в заданные окна контактов. Передача
  может продолжаться в следующих окнах.
- Съёмка и передача не выполняются одновременно; данные удерживают
  **полный объём памяти до окончания передачи** (консервативная модель).
- Сравниваются два правила выбора данных для сброса: FIFO и EDF.
- Успех — **полная доставка** до дедлайна включительно.
- Выходы: `results/comparison.json`, `comparison.csv`,
  `events_fifo.csv`, `events_edf.csv`, `memory_*.csv`.

В этой версии моменты съёмки **заданы**, программа не выбирает, что снимать.
FIFO/EDF оптимизируют только порядок передачи. Нет орбитальной динамики,
энергетики, облачности, планирования группировки, проверки качества кадров
или реального радиолинка. Поэтому результаты — контрольные, не оценка
конкретной космической миссии.

## Запуск без установки библиотек

Нужен Python **3.11 или новее**. Выполнять из папки с файлом `main.py`.

```sh
python main.py
python -m unittest discover -s tests -v
```

На macOS вместо `python` может потребоваться `python3`.

Можно передать свои пути:

```sh
python main.py scenarios/demo.json results
```

Сценарий редактируется в `scenarios/demo.json`. Везде используются
**секунды, байты и байты/секунду**. Все значения демо искусственные.

## Контрольный результат демо

| Политика | Выполнены до срока | Не записаны (память) | K |
|---|---|---|---|
| FIFO | A_fields | C_forest | 1/3 |
| EDF | B_water, A_fields | C_forest | 2/3 |

Оба метода получают один и тот же сценарий. Этот пример только подтверждает,
что программа различает приоритет выбора передачи; он не показывает
статистическое превосходство одного алгоритма.

## Где хранится прогресс

- `PROJECT_STATE.md` — единая точка входа: текущая версия, сделано, не сделано,
  ближайшая задача.
- `DECISIONS.md` — принятые архитектурные решения и допущения.
- `CHANGELOG.md` — история изменений.
- `RESEARCH_CONTEXT.md` — цель НИР, этапы и ключевые научные аналоги.
- `SOURCE_AUDIT.md` — результаты первого просмотра GitVerse и ограничения.

Обновлять эти файлы после каждого законченного этапа. Держать весь каталог
в личном Git-репозитории; архив zip — резервная переносимая копия.

## Правило авторства и лицензий

Код прототипа написан отдельно: файлы GitVerse не копировались.
Перед заимствованием оригинального кода нужно проверить его лицензию и
допустимые условия использования.

## Прозрачность расчётов и Git (дополнение v0.1.1)

Результаты демо — синтетические. Все числа берутся из `scenarios/demo.json`, подробное объяснение каждого — в `docs/INPUT_DATA.md`. Пошаговая логика и сравнение FIFO/EDF — `docs/MODEL_STEP_BY_STEP.md`.

На Windows создайте читаемый HTML-отчёт (без зависимостей):

```powershell
py main.py
py explain.py
start results/report.html
```

В `results/report.html` будут исходные числа, временные диаграммы и полный журнал событий.

Список готовых и предстоящих задач: `TASKS.md`. Для переноса проекта в свой GitHub или GitVerse см. `docs/GIT_WINDOWS.md`.

**Версия 0.1.1 не изменила физическую модель или алгоритм: она сделала расчёт проверяемым и объяснимым.**

Карта файлов и их взаимодействия: `docs/CODE_MAP.md`.
