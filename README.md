# НИРС — исследовательская модель спутника ДЗЗ

**Цель:** исследовать выполнение заданий наблюдения Земли с учётом геометрии, наведения, памяти, энергетики и передачи данных. Все исходные параметры пока **условные**, а не паспорт конкретного КА.

## Быстрый запуск на Windows

1. Установите Python 3.13 x64 с официальным Windows launcher, затем один раз откройте **SETUP_NIRS.cmd** — он создаст `.venv` и установит Basilisk 2.12.2 с научными библиотеками.
2. Каждый следующий раз открывайте **START_NIRS.cmd** — появится русское окно программы.
3. Выберите проверенную физическую модель **двух точечных целей**, новый режим **точечная + полосная съёмка** или многозадачный контрольный эксперимент; нажмите «Запустить».
4. Для проверки всего проекта используйте **CHECK_NIRS.cmd**. Отчёты и графики — в локальной папке **results/**; файл воспроизведения Vizard — через кнопку «Папка Vizard».

**[Подробная инструкция для Windows](docs/WINDOWS_GUI_GUIDE.md)** · [Обновление копии через GitHub Desktop](docs/GIT_WINDOWS.md). Программа не требует VS Code или PowerShell при обычном запуске.

## Состояние модели

- **Physical / Mission 03 (основной режим)**: единая непрерывная физическая симуляция Basilisk с тремя реакционными маховиками, затмением, солнечной панелью, аккумулятором, **двумя последовательными съёмками разных целей**, двумя разделами памяти, радиопередачей и Vizard. Заряд аккумулятора управляет допуском камеры и радиоканала через дискретную бортовую логику. Старая Mission 01 (одна съёмка) сохранена как регрессионный эталон.
- **Mission 04 / универсальный физический исполнитель**: упорядоченная программа из 1–64 точечных и надирных полосных заданий; территории Земли задаются многоугольниками, а фактические подспутниковые положения и угловое наведение — физикой Basilisk. Генерируются последовательные условные порции изображения по мере движения спутника над территорией. Запуск и редактирование доступны через русское окно. **Алгоритма оптимизации здесь нет.**
- **Mission 02**: несколько условных заданий, две станции и сравнение FIFO / EDF / Priority на орбите, предварительно рассчитанной Basilisk. Ограничения поворота, энергии и радиоканала здесь **приближённые**: каждую команду не исполняют физические модули Basilisk.

**Это физический исполнитель заранее упорядоченных заданий, но не цифровой двойник реального КА.** Реально испытаны одно и четыре задания, включая непрерывные полосные порции данных. Универсальный интерфейс программы в JSON реализован, но поиск оптимального порядка намеренно отсутствует. Остаются паспортная калибровка, высокоточная геометрия покрытия, настоящая оптика, приёмник и ошибки датчиков. Mission02 — отдельный упрощённый планировщик.

## Mission 05 — принятая контрольная версия без планировщика

Универсальный физический исполнитель дополнен **плановыми окнами камеры и передачи с отчётом план/факт**, метриками покрытия территорий на **WGS84 с объединением перекрывающихся следов**, эпохой **UTC + поправкой UT1−UTC/приближённым GMST** и обширной физической приёмкой. Параметры аппарата по-прежнему **условные**; алгоритмы оптимизации не добавлены.

**Локальная Windows-приёмка пользователя пройдена 22.11.2026:** 16/16 физических сценариев, 0 ошибок, контрольный коммит `c65daa80c6612a876575337b39f9150223a3c531`. Приложенный baseline также сообщает успешный выход unit tests. Это приёмка синтетической исследовательской модели, а не подтверждение точности реального КА. Четыре GitHub Actions для коммита на момент проверки всё ещё имели статус `queued`; успешный CI не заявляется. [Сводка и следующие задачи](docs/PROJECT_STATUS.md).

Чтобы повторить проверку после изменений кода, запустите `CHECK_RESEARCH_READY.cmd`: он выполняет независимые численные тесты и 16 физических сценариев Basilisk, сохраняя итог в `results/mission05_acceptance_*/acceptance_summary.json`. Успех должен содержать `passed:true`, `pass_count:16` и пустой список ошибок. Если изменялись зависимости, перед этим запустите `SETUP_NIRS.cmd`.
